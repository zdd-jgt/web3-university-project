# 课程内容上传与学习判定 Feature 需求

## Feature 信息

- Feature ID: F-002
- 名称: Course content upload and learning completion
- 环境: 本地 PostgreSQL、Redis、MinIO、FFmpeg/ffprobe
- 执行方式: XJ 严格串行，一次一个 task

## 目标

教师可以为必修课时上传 MP4 视频或常见教学文档。平台不信任浏览器声明的 MIME、大小、时长或对象路径；服务端完成私有上传、实际文件验真、视频标准化转码和明确状态转换。学生购买课程后，通过受保护的学习会话访问内容：视频有效观看覆盖率达到 95% 完成，文档成功访问后由学生确认已阅读完成。全部必修课时完成时，NestJS 原子写入唯一完课记录和证书 Outbox 任务。

## 非目标

- 不部署 AWS、CloudFront、Sepolia 或付费转码服务。
- 不证明学生真正理解或认真观看，只证明受约束的播放/阅读操作。
- 不支持可执行文件、脚本、压缩包或任意未知 MIME。
- 不做 DRM、AI 字幕生成、在线 Office 编辑或移动端流程。
- 本 Feature 不改变 SBT 合约，也不完成 Go 铸证交易可靠性修复；后者属于 F-003。

## 用户故事

- 教师创建课时后，可选择视频或文档，获得短期私有上传地址，并看到上传、处理、就绪或失败状态。
- 学生购买课程后，可播放 READY 视频或访问 READY 文档；没有购买、错链、过期会话或非法内容均无法学习。
- 学生视频覆盖率达到 95% 或确认已阅读文档后，该课时完成；全部必修课时完成后课程进度显示 100%。
- 运营人员可根据失败码区分上传缺失、类型不符、文件损坏、转码失败或存储失败。

## 功能需求

- FR-001: 课时内容类型只能是 `VIDEO` 或 `DOCUMENT`，每个课时最多一个当前内容资产。
- FR-002: 资产状态机为 `UPLOADING -> PROCESSING -> READY | FAILED`；只有显式重试或重新上传才能离开 `FAILED`。
- FR-003: 上传对象 key 由服务端生成，上传会话短期有效并绑定教师、课时、文件名、声明 MIME 和最大字节数。
- FR-004: 文档仅支持 PDF、DOCX、PPTX、XLSX 与纯文本；拒绝脚本、可执行文件、压缩包、双扩展名欺骗和未知类型。
- FR-005: 处理器基于实际字节检查文件签名、大小与 SHA-256；不能用扩展名或浏览器 MIME 直接把资产标记 READY。
- FR-006: 视频输入必须是可探测媒体，处理器用 FFmpeg 输出 MP4/H.264/AAC，并以输出文件重新探测的 MIME、时长、大小和哈希作为 READY 事实。
- FR-007: 文档通过实际 MIME/容器结构检查后原样复制到受保护的 READY key；下载响应使用其实际 MIME。
- FR-008: 课程提交和管理员审批要求所有必修课时都有 READY 资产；视频字幕保持可选，不阻断文档或视频发布。
- FR-009: 学习会话必须从已验证 Privy principal 与当前已购钱包派生，短期有效且不可跨用户、钱包、课时或内容复用。
- FR-010: 视频心跳按会话内递增序号、服务端时间和合理播放位移验收；重复、乱序、超时、跨会话和超过实际持续时间的区间不计入覆盖率。
- FR-011: 文档必须先建立访问会话并成功取得短期读取 URL，之后学生显式确认已阅读；确认接口幂等。
- FR-012: 视频覆盖率达到 95% 或文档确认完成时写唯一课时完成事实；所有必修课时完成时在同一可重试事务中写唯一 `CourseCompletion` 与唯一 `certificate.mint` Outbox。

## 非功能需求

- NFR-001: 上传大小、会话 TTL、处理超时与并发数有显式上限；默认本机一次处理一个资产。
- NFR-002: Node 命令使用仓库固定 Node 24/pnpm；所有重型检查严格串行。
- NFR-003: 原始与 READY 内容均私有；公开响应不得泄漏对象 key、存储凭据或本地绝对路径。
- NFR-004: 数据库迁移必须保留现有 `VideoAsset` 数据或明确给出仅本地可恢复路径，并在真实 PostgreSQL 上验证。
- NFR-005: token 估算只用于规划；无法观测真实 token 时记录 `unavailable`，不得伪造。

## 边界情况

- 上传会话过期、对象不存在、实际大小不符、零字节、超限、MIME/扩展名冲突或处理器重启均不得产生 READY 假状态。
- 同一课时并发创建上传会话只能有一个当前有效资产；替换必须使旧会话和旧 READY key 失效。
- 学生切换钱包后，未购买钱包不能复用之前签发的学习会话。
- 视频暂停不产生进度；快进、后台伪造超大区间、重复心跳和序号回退不增加覆盖率。
- 文档仅打开 URL 不自动完成；未成功建立访问会话不能确认已阅读。
- 并发达到最后一个必修课时完成时，只能创建一条完课记录和一条 Outbox。

## 验收标准

- AC-001: Prisma 与迁移表达 VIDEO/DOCUMENT、完整资产状态机和服务端验真字段，真实 PostgreSQL 可迁移。
- AC-002: 教师只能为自己的 DRAFT 课程课时创建短期、限大小且服务端生成 key 的上传会话。
- AC-003: 非允许类型、伪造 MIME、错误大小、损坏文件和过期上传均失败且不会 READY。
- AC-004: 有效视频被标准化为可探测 MP4/H.264/AAC，有效文档保留实际 MIME；两者均记录大小和 SHA-256 后 READY。
- AC-005: 处理失败可观察且可安全重试，不会同时存在两个当前 READY 资产。
- AC-006: 课程提交/审批接受 READY 视频或文档，拒绝缺失、UPLOADING、PROCESSING 或 FAILED 的必修资产。
- AC-007: 未购买、错链、错用户/钱包、过期或重放学习会话不能取得内容或写入进度。
- AC-008: 视频只累计通过序号、时间和位移校验的片段，合并覆盖率达到 95% 才完成。
- AC-009: 文档必须先访问后确认，重复确认幂等并形成唯一课时完成事实。
- AC-010: 所有必修课时完成后进度为 100%，并发重复请求仍只有唯一 Completion 与 Outbox。
- AC-011: 教师和学生桌面页面能完成上传状态查看、视频学习和文档访问/确认，失败可恢复且不把 Demo 当 live 数据。
- AC-012: 聚焦测试、API 类型检查、真实 PostgreSQL 集成和本地 MinIO/FFmpeg 处理证据全部通过；未执行的浏览器层明确标记。

## 依赖

- 现有 NestJS、Prisma、PostgreSQL、MinIO、Privy principal 与链上购买权益投影。
- 本地 FFmpeg/ffprobe，可通过本地容器提供；不调用外部服务。
- 现有 React/Vite 桌面 Web。

## 开放问题

- 无。用户已确认文档在成功访问后由学生点击“确认已阅读”完成。
