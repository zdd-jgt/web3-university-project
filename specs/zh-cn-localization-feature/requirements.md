# 正经打工人的 web3大学中文本地化需求

## 目标

- 将平台品牌统一为“正经打工人的 web3大学”。
- 平台自有、用户可见文案默认使用简体中文。
- 在 Privy 当前 SDK 支持的范围内覆盖登录与连接钱包界面的中文文案。
- 将服务端返回的学习状态码和媒体失败码转换成中文说明，同时保留必要诊断码。
- 日期、时间和数字显式使用 `zh-CN` 格式，不依赖操作系统或浏览器默认语言。

## 非目标

- 不翻译协议、网络、币种、标准或地址标识，例如 Web3、Sepolia、ETH、USDT、YD、Uniswap、Privy、Chainlink、RPC、API、MIME、MP4、IPFS、EIP-712。
- 不修改用户、教师自行填写的课程标题、评论或用户名。
- 不修改认证、权限、API、数据库、合约或交易行为。
- 不承诺覆盖 Privy SDK 未开放本地化键的第三方内置文案。

## 用户故事

- 作为中文用户，我进入任意平台页面时，应看到统一的中文品牌与操作文案。
- 作为学生，我看到学习心跳被拒绝时，应理解原因，而不是只看到英文状态码。
- 作为教师，我看到媒体处理失败时，应先看到中文原因，并能保留诊断码用于排查。
- 作为任何用户，我看到日期、时间和数字时，应获得稳定的中文格式。

## 功能需求

- FR-001：网页标题、页头、页脚和无障碍品牌标签统一使用“正经打工人的 web3大学”。
- FR-002：Privy 登录入口标题、说明和当前 SDK 开放的钱包连接文案使用中文。
- FR-003：学习心跳原因 `BASELINE/PLAYING/PAUSED/SEEK/STALE` 映射为中文。
- FR-004：已知上传与媒体处理失败码映射为中文，未知码使用中文兜底并保留原码。
- FR-005：平台控制的日期、时间和数字统一通过 `zh-CN` 格式化。

## 非功能需求

- 不新增依赖。
- 映射与格式化逻辑集中维护，调用页面不复制相同知识。
- 未知服务端状态必须安全降级，不能显示空白或误报成功。

## 边界情况

- 未知心跳原因或失败码：显示中文通用说明，并在括号内保留原始诊断码。
- 无效日期：显示“时间未知”，不能抛出渲染异常。
- Privy 未开放的本地化字符串：保留 SDK 行为，并在验收报告中明确限制。

## 验收标准

- AC-001：浏览器标题、页头、页脚和品牌无障碍名称均显示“正经打工人的 web3大学”。
- AC-002：Privy 配置包含中文入口文案和当前 SDK 支持的钱包连接本地化键。
- AC-003：用户界面不直接裸露已知学习原因码或媒体失败码，中文说明后可保留诊断码。
- AC-004：日期、时间和数字格式显式指定 `zh-CN`，在英文系统默认语言下仍输出中文格式。
- AC-005：相关组件测试、前端类型检查、Biome 和本地浏览器验收通过。

## 依赖与开放问题

- 依赖已安装的 Privy React SDK 3.37.1；其 `intl.textLocalization` 只开放部分钱包连接字符串。
- 无待确认的外部服务、费用、密钥或部署动作。
