# 正经打工人的 web3大学中文本地化设计

## 第一性原理

用户需要的是可理解且稳定的中文界面，而不是“源码中大部分字符串被替换”。平台必须同时控制静态文案、第三方 UI 配置、服务端状态解释和环境相关格式化，才形成完整中文体验。

## 用户可观察结果与不变量

- 所有平台页面使用同一品牌名称。
- 已知状态先呈现中文含义，技术诊断码只作为辅助信息。
- 相同时间和数字在不同系统语言下保持中文格式。
- 技术协议名、钱包地址、交易哈希和合约字段不被误翻译。
- 认证、购买、学习进度和媒体处理语义保持不变。

## 信任边界与失败方式

- Privy UI 属于第三方组件，只能覆盖 SDK 公开的本地化入口；不能伪称完整翻译第三方内部所有页面。
- 心跳原因和媒体失败码来自服务端，不允许直接作为用户文案；未知值必须中文兜底。
- 浏览器默认 locale 不可信，必须显式指定 `zh-CN`。

## 方案比较

### 方案 A：各页面就地翻译和调用 `toLocaleString("zh-CN")`

- 优点：初始改动直接。
- 缺点：状态映射、日期格式和未知值规则分散，容易产生页面间不一致，后续新增调用者需要重复理解。

### 方案 B：集中本地化边界，页面只调用小接口（采用）

- 新增 `apps/web/src/lib/localization.ts`，拥有品牌、`zh-CN` 格式、学习原因和媒体失败码的解释知识。
- 页面保留领域编排，不知道映射表细节。
- Privy 配置在 `runtime.tsx` 内就近维护，因为该第三方配置只属于认证边界。

选择原因：方案 B 用少量稳定接口隐藏跨页面的本地化知识，减少变化放大，同时没有引入完整 i18n 框架或新依赖。

## 模块与接口

- `localization.ts`
  - `PLATFORM_NAME`
  - `formatZhDateTime`、`formatZhTime`、`formatZhNumber`
  - `learningReasonLabel`
  - `assetFailureLabel`
- `runtime.tsx`
  - Privy `appearance.landingHeader/loginMessage`
  - Privy `intl.defaultCountry/textLocalization`
- 页面与组件
  - 使用集中格式化和状态解释函数。

## 测试与证据

- 纯函数测试覆盖已知、未知状态和无效日期。
- 组件测试验证中文状态和品牌文案。
- 运行全部前端测试、类型检查与 Biome。
- 浏览器抽查首页、学习页、兑换页和个人中心；Privy 无真实 tenant 时以类型检查和配置静态证据为限。

## 回退

本地化变更不涉及持久化状态。回退时恢复调用点和 Privy 配置即可，不需要数据库或链上恢复。
