# YD 固定供应量调整设计

## 第一性原理

用户需要的是可审计、不可被管理员任意稀释的 8,000 万 YD 总供应量。最小充分设计是修改唯一供应事实 `INITIAL_SUPPLY`，继续由构造函数一次铸给 Treasury，而不是加入未被当前需求证明有必要的增发权限。

## 不变量

- 总供应量精确为 `80_000_000 * 10^18` 最小单位。
- Treasury 不能为零地址，且部署后持有全部初始供应。
- 不存在构造后增发路径；`totalSupply` 只能因 ERC20 转账保持不变。
- 名称、符号、小数位、课程支付和分账逻辑不变。

## 方案比较

### 方案 A：固定发行 80,000,000 YD（采用）

- 只修改供应常量及对应测试/文档。
- 接口不变、权限面不扩大、未来 Sepolia 部署参数确定。
- Treasury 通过储备转账控制流通量，不需要增发。

### 方案 B：初始 80,000,000 YD 加上限增发（不采用）

- 需要 `MINTER_ROLE`、最大供应、权限撤销、多签与时间锁等新信任边界。
- 当前教学测试网没有证明这些复杂性必要，且会削弱固定供应承诺。

## 模块边界与失败方式

- `YDToken.sol` 独占总供应量与初始铸币事实。
- Foundry 测试验证精确总量、Treasury 余额、零地址失败和 CourseMarket 回归。
- README 与架构文档只同步已经由代码和测试表达的事实。
- 若未来部署后发现供应量错误，原合约不可修改；停止使用错误地址并部署新版本。本任务不执行部署，因此本地回退是恢复这次 diff。

## 安全与发布边界

- 不保存私钥、助记词、RPC URL 或 Treasury 真实地址。
- 不广播交易，不验证 Etherscan，不创建或注资 Uniswap 池。
- 本地测试通过只能证明制品行为，不能声称 Sepolia 已部署。
