# 教师、管理员与评论工作流收口 Requirements

## 目标

把当前工作树中已经存在的教师工作台、管理员审核台和课程评论改动收口为可审计的本地功能：服务端权限保持权威，前端在 Demo、未登录、失败和成功状态下给出可信反馈，并以 XJ 事件链、自动化测试和本地视觉证据完成验收。

## 非目标

- 不部署 Sepolia、云服务、The Graph 或真实 Privy tenant。
- 不发送管理员链上交易；只展示服务端生成的 publication package。
- 不把真实 MinIO/S3 上传处理闭环冒充为本任务证据；该闭环仍由课程内容 T-006 验收。
- 不新增购买历史、学生学习界面或证书失败队列。

## 用户故事

- 申请教师的用户可以提交申请并查看状态，管理员可以只处理待审核申请。
- 已获教师权限的用户可以管理草稿、课时、受保护资产声明和发布申请。
- 管理员可以审核课程、恢复 publication package，并以原因隐藏或恢复评论。
- 公开访客可以阅读已发布课程的可见评论；已购学生可以发顶层评论，课程教师可以回复顶层评论。

## 功能需求

- FR-001：所有教师、管理员写操作必须携带认证会话，最终角色和对象权限由 NestJS 校验。
- FR-002：教师申请队列只返回 `PENDING`；同一申请只能从 `PENDING` 原子迁移一次。
- FR-003：教师草稿页面必须接通草稿、课时、上传会话、finalize、状态轮询和发布申请 API，并在必修资产未 `READY` 时禁用提交。
- FR-004：管理员课程审核只生成或恢复 publication package，页面不得签名或发送链上交易。
- FR-005：顶层评论要求当前购买钱包拥有课程权益；回复只允许课程教师创建，且 parent 必须是同课程、可见的顶层评论。
- FR-006：评论审核队列仅管理员可见；隐藏和恢复都必须提供规范化后的审核原因。
- FR-007：Demo、缺 API、未登录或无钱包时，页面必须 fail closed，不发送写请求。
- FR-008：HTTP 失败必须映射为不泄露内部细节且可恢复的用户提示。

## 非功能需求

- NFR-001：不记录或提交 Token、私钥、RPC Secret、个人敏感信息。
- NFR-002：列表具有服务端上限；本任务不增加无界查询。
- NFR-003：前端核心控件具备标签、可见焦点、disabled/busy 和错误状态。
- NFR-004：XJ 派生 run-state 不进入 Biome 格式化范围，避免机械修改审计派生数据。

## 边界情况

- 非管理员直接请求教师、课程或评论审核队列。
- 非课程教师传入 `parentId`，或教师传入一个回复的 ID 试图创建二级嵌套回复。
- 重复审核同一教师申请或课程审核发生冲突。
- 必修课无资产、资产未 READY、非法价格/钱包/IPFS URI。
- API不可用、Privy未登录、钱包未连接、请求返回401/403/409/429/503。

## 验收标准

- AC-001：教师和管理员页面在 Demo/未认证边界不发送受保护请求，并显示明确原因。
- AC-002：教师申请、草稿、课时、上传声明、发布申请和管理员审核 API 接线通过组件/客户端测试。
- AC-003：非管理员无法读取审核队列；教师申请审核保持原子单次迁移。
- AC-004：评论读取、已购发帖、课程教师顶层回复、管理员有原因审核均由服务端约束；二级嵌套回复被拒绝。
- AC-005：管理员课程审核只展示 publication package，不发送链上交易。
- AC-006：API和Web聚焦测试、API/Web类型检查、Web构建及任务范围Biome检查通过。
- AC-007：桌面与平板的本地页面路由、Demo阻断提示、表单标签和焦点样式具有视觉证据。
- AC-008：状态文档只声称本地Mock/组件证据，明确真实上传、Privy和链上动作未验证。

## 依赖

- 复用现有 NestJS、React Query、Privy runtime、课程/媒体 API 和 XJ Harness。
- Git baseline：当前 `b631e3a`；采用用户明确要求“先收口”的现有工作树改动。
